# Staged launch checklist

Selected route: v0.1.1 public-following preview. Marketing work does not add runtime capabilities. Link technical checks to the [release checklist](../release-checklist.md) and evidence to the [claim ledger](claim-ledger.md).

## Stage 1: internal comprehension

- [ ] Five consenting unfamiliar adults actually complete the [pilot](pilot.md).
- [ ] Record first exposure, exact copy, unaided responses and every criterion n/5.
- [ ] At least 4/5 understand core claims; correct date/scope/readiness errors regardless of composite.
- [ ] Record actual fixes and a new round where needed. No simulated participants.

## Stage 2: controlled offline preview

- [ ] Final local package/skill checks pass for exact commit.
- [ ] Five-to-ten consenting compatible users attempt setup with synthetic data.
- [ ] Count missing prerequisites, help, time, failures, source/data preservation.
- [ ] Finalize feedback-dependent preview/card/carousel/videos and accessibility.
- [ ] Select one rented platform using real preferences/capacity; choose any existing consented owned channel.
- [ ] Approve exact recipients/content and publish the controlled preview only afterward; verify readback.

## Stage 3: separately authorized live pilot

- [ ] Choose a supported runtime/release and revalidate every feature/pin.
- [ ] Resolve collection bounds/reservation limits before claims of dependable unattended use.
- [ ] Obtain target-specific authority and human-created login reference without secrets in chat.
- [ ] Successful authorized manual public collection, with complete evidence.
- [ ] For any daily feature, actual supported-host registration and invocation.
- [ ] For any alerts claim, selected channel, authorized payload and real confirmed-event delivery. Acceptance, device display and read acknowledgement remain distinct.
- [ ] At least three consecutive actual successful scheduled daily windows, with gaps/failures recorded. Synthetic time and no-event days cannot prove real-event delivery.

None of Stage 3 ran in this marketing task. v0.1.1 does not supply built-in alerts. A later release's worktree or source tests cannot substitute for that release's live evidence.

## Stage 4: broader promotion

- [ ] A usable consumer route exists before consumer/dating creator campaigns.
- [ ] Real comprehension/setup findings support the current story.
- [ ] Audience/channel/pricing decisions include counterexamples and denominators.
- [ ] Original final assets and claims reviewed against the exact released product.
- [ ] Exact account, recipients, content, cost and publication actions approved.
- [ ] Actual link/image/caption/readiness readback matches the approved draft.

Open-source popularity or virality does not establish installation ease, dependable operation, demand or useful interpretation. No launch date, recurring campaign or paid offer is created by this checklist.
